Intégrer la page d'accueil dans WordPress

Koytcha Immo — marche à suivre, environ 20 minutes.

⬇ Télécharger la page complète (HTML)

Fichier autonome : toutes les images et polices pointent vers des adresses absolues. Ouvrez-le en double-cliquant dessus pour vérifier avant de l'intégrer.

Si le clic ouvre la page au lieu de la télécharger : clic droit → « Enregistrer la cible du lien sous… ». Ouvrir dans un onglet

⬇ Télécharger les images et les polices (ZIP, 3,1 Mo)

Les 22 images et 9 polices réellement utilisées par la page, à téléverser dans la médiathèque. Un fichier A-LIRE.txt à l'intérieur explique quoi faire ensuite — et pourquoi les polices .otf demandent un traitement à part.

⬇ Télécharger le bloc pour Elementor (widget HTML)

Le contenu de la page, sans <html> ni <head>, avec les chemins d'images déjà en adresses absolues et un bloc de compatibilité Elementor en tête. À coller tel quel dans un widget HTML. Voir la méthode C plus bas.
Avant de commencer : faites une sauvegarde.

Une sauvegarde complète du site et de la base de données. Si un réglage tourne mal, c'est ce qui vous permet de revenir en arrière en cinq minutes au lieu de passer la journée dessus.

1Choisir la méthode

Deux voies, selon ce que vous voulez garder de l'existant.

MéthodeQuand la choisir
A — Modèle de page
recommandée		 La page reste du HTML/CSS pur. Rendu identique au pixel près, le plus rapide à charger. En revanche Florent ne pourra pas la modifier depuis Elementor.
C — Widget HTML Elementor
le plus rapide		 La page entière dans un seul widget HTML, sur une page en modèle Elementor Canvas. Même rendu que la méthode A, sans toucher au thème enfant. C'est la voie à prendre si vous travaillez déjà dans Elementor.
B — Reconstruction Elementor Chaque section est refaite avec les widgets Elementor. Beaucoup plus long, et les effets (Ken Burns, néon au survol, miroir) demandent quand même du CSS personnalisé. À réserver au cas où l'équipe doit éditer la page elle-même au quotidien.

2Méthode A — poser un modèle de page

a. Déposer le fichier dans le thème enfant

Renommez le fichier téléchargé en page-accueil-koytcha.php et placez-le à la racine de votre thème enfant. Jamais dans le thème parent : la prochaine mise à jour l'écraserait.

Ajoutez ces quatre lignes tout en haut du fichier, avant le <!doctype html> :

<?php
/* Template Name: Accueil Koytcha 2026 */
?>

C'est cet en-tête, et lui seul, qui fait apparaître le modèle dans WordPress.

b. Affecter le modèle à la page

  1. Créez une page (ou ouvrez la page d'accueil actuelle).
  2. Dans le panneau de droite, section Attributs de page, choisissez Accueil Koytcha 2026.
  3. Publiez, puis regardez le résultat.
Le mieux est de tester sur une page temporaire d'abord — par exemple /nouvelle-accueil/. Vous basculez la vraie page d'accueil seulement une fois que tout est vérifié, dans Réglages → Lecture.

c. Rapatrier les images sur votre serveur

Dans le fichier livré, les images pointent vers previsualisation.automatisationboost.com. Ça fonctionne immédiatement, mais votre site dépend alors d'un serveur qui n'est pas le vôtre. Pour être autonome :

  1. Téléversez les images dans la médiathèque WordPress.
  2. Dans le fichier, remplacez chaque https://previsualisation.automatisationboost.com/koytcha-refonte-v5/assets/ par l'adresse de votre médiathèque (https://koytchaimmo.re/app/uploads/2026/09/ par exemple).

Un « Rechercher / Remplacer » dans un éditeur de texte suffit, c'est la même chaîne partout.

3Méthode C — le widget HTML d'Elementor

C'est la voie où l'on se fait piéger le plus souvent : la page s'affiche, mais elle n'occupe qu'une colonne au milieu de l'écran, et le menu du thème reste au-dessus de celui de la page. Deux menus superposés, deux fois la même navigation. Les trois réglages ci-dessous règlent ça.

a. Mettre la page en modèle « Elementor Canvas »

Dans l'éditeur Elementor : roue crantée en bas à gauche → Mise en page → Modèle de page → Elementor Canvas. Puis mettez à jour.

ModèleCe qu'il fait
Elementor Canvas Page nue : ni en-tête ni pied de page du thème, aucune largeur imposée. C'est celui qu'il faut ici — la page apporte déjà sa propre barre de navigation.
Elementor Pleine largeur Pleine largeur, mais garde l'en-tête et le pied du thème. D'où le menu en double. Ce n'est pas celui-là.
Par défaut / du thème En-tête, pied, et contenu borné à la largeur du thème. C'est le réglage de départ, celui qui écrase la page.
Le choix « Elementor Canvas » n'apparaît pas dans la liste ?

Trois causes, dans l'ordre où il faut les vérifier :

  • La page n'est pas éditée avec Elementor : hors de l'éditeur Elementor, le réglage se trouve dans Attributs de page → Modèle, colonne de droite. S'il n'y est pas non plus, cliquez d'abord sur Modifier avec Elementor.
  • Le thème filtre la liste des modèles. Testez avec un thème neutre (Hello Elementor) sur une page temporaire : si Canvas réapparaît, c'est le thème.
  • Elementor n'est pas activé pour le type de contenu Page : Elementor → Réglages → Général → Types de publication.

Dans tous les cas, le bloc livré contient un filet de sécurité en CSS qui masque l'en-tête et le pied du thème et rend la pleine largeur. Il dépanne, mais mieux vaut le vrai modèle Canvas : masquer un menu, ce n'est pas la même chose que ne pas le charger.

b. Dé-brider la section et la colonne

Même en Canvas, Elementor borne le contenu de chaque section et pose des marges internes.

  • Section → Mise en page → Largeur du contenu = Pleine largeur, et Étirer la section = Oui.
  • Colonne → Avancé → Marge intérieure = 0 sur les quatre côtés.
  • La page gère ses propres gouttières (la classe .wrap) : si vous laissez celles d'Elementor, tout est en retrait deux fois et le plein écran du haut n'en est plus un.

c. Coller le bloc

Ajoutez un widget HTML dans la colonne, et collez-y le contenu de bloc-elementor.html (lien de téléchargement en haut de cette page). Il contient déjà les feuilles de style, les images en adresses absolues et le filet de sécurité.

Pour récupérer le texte : ouvrez le fichier téléchargé dans un éditeur de texte (Bloc-notes, TextEdit, VS Code), Ctrl+A puis Ctrl+C. Évitez de copier depuis la fenêtre du navigateur : selon la façon dont il interprète le fichier, vous pouvez embarquer des accents cassés.

Des accents en « Ã© » après le collage ?

Le texte a été abîmé au moment de la copie, pas par WordPress : recoller la version corrigée est la seule façon de le réparer, un rechercher/remplacer ne rattrape jamais tous les cas. Le fichier est en UTF-8 et le serveur l'annonce désormais explicitement — si votre éditeur propose un encodage à l'ouverture, choisissez UTF-8.

Barre d'administration WordPress.

Connecté, WordPress ajoute une barre de 32 px en haut de l'écran. La navigation de la page étant en position fixe, elle passerait dessous et le logo serait coupé. Le bloc décale la barre de navigation quand cette barre est présente — c'est pour ça que la page ne se pose pas au même endroit selon que vous êtes connecté ou non.

4Le module de recherche

Sur WordPress, ne gardez pas le bloc tel quel — mettez le widget Elementor.

Le fichier livré contient une copie du module qui fonctionne hors WordPress grâce à un React chargé depuis un CDN. Sur votre site, WordPress fournit déjà ce React : insérez simplement le widget Search KTP à l'emplacement prévu, et supprimez du fichier les trois lignes marquées <!-- ORDRE IMPORTANT --> ainsi que le bloc window.wp.element à la fin.

L'emplacement est repérable dans le fichier : cherchez class="boite". C'est le conteneur en verre dépoli du premier écran.

L'habillage aux couleurs de la nouvelle page est porté par les règles CSS commençant par .boite .app. Gardez-les si vous voulez le même rendu sombre ; supprimez-les pour retrouver l'apparence d'origine du module.

5Vérifier avant de basculer

  • Le module de recherche affiche un nombre de résultats et le bouton mène bien aux annonces.
  • Le menu s'ouvre sur téléphone et les sous-menus se déplient.
  • Les cinq réalisations portent le bon nom sous la bonne photo.
  • Le pied de page : 45 rue Alexis de Villeneuve, contact@koytchaimmo.re, pas de samedi.
  • Aucune erreur rouge dans la console du navigateur (touche F12, onglet Console).

8Sécurité — cinq failles relevées, à corriger avant la mise en ligne

Constats d'un audit en lecture publique sur koytchaimmo.re (rien de plus qu'un navigateur). Deux se corrigent avec une extension, deux avec quelques lignes dans le thème enfant (le même endroit que page-accueil-koytcha.php), un dernier au niveau du serveur.

ConstatPortée

a. L'extension pour les en-têtes : HTTP Headers

Gratuite en totalité (pas de palier Pro caché), 50 000+ installations actives, se règle depuis l'admin sans toucher au code. C'est le seul point de la liste qui a vraiment intérêt à passer par une extension plutôt qu'un fichier .htaccess : les 40+ en-têtes qu'elle gère sont listés et modifiables un par un, alors qu'un en-tête mal formé dans .htaccess peut faire planter tout Apache (erreur 500 sur tout le site) sans message clair.

# Depuis le dossier racine WordPress, en SSH :
wp plugin install http-headers --activate

# Site en Bedrock (composer.json à la racine du projet, pas dans web/) :
composer require wpackagist-plugin/http-headers
wp plugin activate http-headers

Réglages à poser dans Réglages → HTTP Headers (valeurs de départ raisonnables pour un site Elementor + Contact Form 7 — testez avant de basculer en production, un CSP trop strict casse des widgets avant de bloquer des attaquants) :

Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https:; style-src 'self' 'unsafe-inline' https:; img-src 'self' data: https:; font-src 'self' data: https:; frame-ancestors 'self';
Le CSP ci-dessus est volontairement permissif.

Elementor, Contact Form 7 et le widget de recherche KTP injectent du CSS et du JS en ligne : un CSP strict (sans unsafe-inline) casse la mise en page avant de gêner qui que ce soit. Si l'extension propose un mode « rapport seul », commencez par là une semaine, regardez ce qui remonte, puis serrez la règle.

b. Masquer les versions et fermer l'énumération REST — dans functions.php du thème enfant

Pas d'extension nécessaire : quatre filtres, au même endroit que le modèle de page déposé en étape 2.

// Masquer la version WordPress (balise <meta name="generator"> + flux RSS)
remove_action('wp_head', 'wp_generator');
add_filter('the_generator', '__return_empty_string');

// Fermer /wp-json/wp/v2/users pour les visiteurs non connectés
add_filter('rest_endpoints', function ($endpoints) {
    unset($endpoints['/wp/v2/users']);
    unset($endpoints['/wp/v2/users/(?P[\d]+)']);
    return $endpoints;
});

Pour x-powered-by: PHP/8.4.24, WordPress n'y peut rien — c'est PHP qui l'ajoute. Deux leviers, du plus simple au plus fiable :

  • Si mod_headers est actif (Apache) : Header unset X-Powered-By dans le .htaccess à la racine.
  • Sinon, demandez à l'hébergeur de passer expose_php = Off dans php.ini — c'est le seul réglage qui marche à coup sûr, .htaccess ne le peut pas partout.

c. Fermer /debug.log — un réglage serveur, pas une extension

Un fichier de log ne se « sécurise » pas avec un plugin : soit il est joignable en HTTP, soit il ne l'est pas. Deux étapes, dans l'ordre.

Immédiat — bloquer le fichier existant via .htaccess à la racine :

<Files debug.log>
Require all denied
</Files>
# Apache < 2.4 : remplacer par "Deny from all"

Durable — dans config/application.php (Bedrock), pointer le log vers un chemin hors de web/, le dossier servi publiquement, au lieu de le laisser à true (ce qui l'écrit dans le dossier de contenu, donc accessible) :

define('WP_DEBUG_LOG', dirname(__DIR__) . '/storage/logs/debug.log');
Vérifiez le chemin réel avant de coller ce réglage.

L'audit a trouvé le fichier à la racine (koytchaimmo.re/debug.log), pas à l'emplacement par défaut de Bedrock (web/app/debug.log) — la structure de ce projet a peut-être été adaptée. Confirmez en SSH/FTP avant de choisir le nouveau chemin, et supprimez l'ancien fichier une fois le nouveau en place.

d. Vérifier après coup

Depuis un terminal, sans rien d'autre qu'un navigateur en ligne de commande :

curl -sI https://koytchaimmo.re/ | grep -i "strict-transport\|x-frame\|x-content-type\|referrer-policy\|content-security\|x-powered-by"
curl -s -o /dev/null -w "%{http_code}\n" https://koytchaimmo.re/debug.log
curl -s https://koytchaimmo.re/wp-json/wp/v2/users

Attendu : les cinq en-têtes présents, debug.log en 403 ou 404, x-powered-by absent, et /wp-json/wp/v2/users qui ne renvoie plus koytchaimmo@gmail.com.
