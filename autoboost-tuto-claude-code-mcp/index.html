Pourquoi le hook enchaîne sur le tuto

Le clip s'ouvre sur Tony au volant d'un buggy — hors sujet, donc on regarde. À 5,6 s il lève l'index, à 6,3 s son doigt couvre l'objectif : le volet fait office de coupe. Derrière, la caméra retombe sur lui assis devant un mur d'écrans de code. Le clip fournit donc lui-même le raccord « vie → poste de travail » : la promesse est tenue par l'image avant d'être tenue par la voix. Le hook sort pile sur ce plan bureau, et l'étape 01 démarre.

Les captures

Étapes 01 et 02 — sorties de commandes RÉELLES. J'ai lancé les commandes ici avant de filmer : npm install -g @anthropic-ai/claude-code → « added 2 packages in 15s » ; claude --version → « 2.1.235 (Claude Code) » ; claude mcp add --transport http n8n … → « Added HTTP MCP server n8n with URL… to local config » ; claude mcp list → les lignes « ✔ Connected ». Le texte à l'écran est celui qu'ont réellement renvoyé ces commandes, au caractère près.

Ce qui est reconstitué — à savoir

  • Le châssis de fenêtre et le curseur sont dessinés : il n'y a pas de session graphique ici, donc rien à filmer à l'écran. La frappe est jouée caractère par caractère, le curseur se déplace et le clic fait pulser un halo.
  • Étape 03 (la TUI Claude Code) est une reconstitution complète. Lancer un vrai claude -p imbriqué est bloqué par un hook de session, et le faire tourner dans un profil isolé demandait de recopier les identifiants — je ne l'ai pas fait. Le contenu affiché reprend la forme réelle de la TUI et un vrai nom d'outil MCP n8n, mais ce n'est pas un enregistrement.
